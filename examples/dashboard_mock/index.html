    Local UI testing instructions

    Open PowerShell in the folder containing main.py and this index.html. Create a fresh virtual environment if the copied environment points to another computer.

    python -m venv .venv-dashboard
.\.venv-dashboard\Scripts\python.exe -m pip install -r requirements.txt
.\.venv-dashboard\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000

    Keep that terminal running and open http://localhost:8000/. For another PC on the same network, use the server computer's IP address and port 8000.

    1. Apply settings, wait for CONFIG_APPLIED, then Start.
    2. Use a shorter production cycle than inspection time to fill the queue.
    3. Try Pause, Resume and Stop. Check the reported command phases and final report.
    4. Use Simulate fault to test the mock Fault and Reset controls.
    5. Refresh or reconnect, then reapply the displayed settings before starting another batch.
    Future Gateway Integration Requirements

    The current mock supplies aggregate counts, operation IDs, configuration version and online flags. The UI shows Not reported for optional details that are unavailable.

    • Station readiness, local state, heartbeat age, boot ID and session ID can use flat fields such as esp32_a_ready, esp32_a_state, esp32_a_heartbeat_age_ms, esp32_a_boot_id and esp32_a_session_id, with equivalent ESP32 B fields.
    • Full applied configuration values tied to a version would allow authoritative restoration after a refresh. Currently, settings confirmed in this browser are labeled with their source and must be reapplied after reconnecting.
    • Stable event IDs and gateway timestamps improve event reconciliation. Without them, command history uses best-effort occurrence matching.
    • Optional result_age_ms, quarantine/reconciliation status and per-job configuration versions can populate warning and result details when supplied.
    • Batch start/end timestamps, duration, final queue occupancy, abortion reason and can_reset_fault are displayed when available. The current mock provides no exact operation countdown data.
    Operator controls use the existing FastAPI commands and WebSocket status stream.
